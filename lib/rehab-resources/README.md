# 復健科補助與援助資源

此目錄為 `/rehab-resources` 的公開靜態資料，不儲存患者資訊，也不執行補助審核。

## 收錄與更新

- `national.ts`：全國性政府、民間方案及服務入口。
- `official-links.ts`：集中管理1966長照首頁、各縣市照管中心電話頁與給付制度來源，保留三種用途；查無結果的連結文字依實際目標頁顯示。
- `central-government.ts`：彰化、南投、臺中、雲林政府方案。
- `central-community.ts`：中部基金會、慈善會與醫院方案／社工入口。
- `expanded-changhua-taichung.ts`、`expanded-nantou-yunlin.ts`：中部四縣市擴充的政府方案與服務。
- `expanded-central-community.ts`：擴充的中部民間及醫院方案與服務。
- `provider-hospitals.ts`、`provider-central-nonprofits.ts`、`provider-local-associations.ts`、`provider-supplement.ts`：以不同單位擴充的醫院、基金會及地方團體。
- `regional-contacts.ts`：22 縣市官方窗口；不計入補助方案數。
- `prerequisites-health.ts`、`prerequisites-insurance.ts`：身障鑑定、重大傷病、PAC、職災、普通勞保失能及車禍保險／特補制度，附獨立條件和官方程序。這些制度不是每個人都須先辦，也不是全部福利的共同前提。
- `disease-specific.ts`：有實際專屬窗口才開放的帕金森、ALS、截肢義肢入口；沒有把尚無完整辦法的補助一併推定可申請。
- `counties.ts`：彰化、南投、臺中、雲林公開內容頁的固定 slug、標題與說明。
- `publication.ts`：公開資料與指南的核對門檻、暫不公開清單；`freshness.ts`：完整、僅窗口、隱藏三階段及負面證據；`report.ts` 僅以已公開資源 ID 產生 LINE 回報連結。
- `types.ts`：疾病、需求、地區及方案欄位。
- `matching.ts`：篩選、台灣日期、受理狀態及待複核判斷。
- `review-warnings.ts`：建置時的28天規則降級、30天窗口隱藏提醒，依轉換日期分組。
- `providers.ts`：將同一政府、基金會及單位的服務合併呈現及計數。

每個方案獨立記錄，區分現金補助、服務轉介及制度指引。引用可查閱的政府或機構第一手頁面，不因機構名稱推定全國服務，也不補造專款、資格或金額。來源暫時無法讀取時，須明示核對限制。

畫面與收錄目標以不同「單位」為準，不能以方案數充當單位數。同縣市政府各科室合併，同基金會各據點合併；已知受託單位有明確對應。不同服務仍保留各自的資格、窗口、狀態及來源，放在同一張單位卡片內。加入討論清單時保存該次符合條件的服務，列印依單位分組。

政府輔具及全台早療制度指引保留於「相關網頁」，不以「各縣市政府」等非單一單位名稱灌入結果數。選擇中部以外縣市時，該縣市官方窗口卡片會直接出現在查詢結果上方，與補助單位分開計數。網站標題與結果明示「中部四縣市為主・全台政府窗口」，不宣稱18個尚未逐筆整理的縣市已有完整在地方案。

搜尋先列完整資料，再列僅保留窗口的資料；各組內為病別相關服務優先，再依符合需求數、所選縣市重疊排序。同一單位以最相關的一項服務評分，不以服務數灌排名；單位內服務也採相同排序。若同一單位同時有完整與逾期服務，完整服務排在前面，逾期服務各自降級，不拖累整個單位。職災或事故原因型制度以 `diseaseSpecific: false` 避免因導覽病別標籤而誤獲專屬加權。若已選單位在其他查詢有新增服務，可合併加入原單位清單，不增加單位數。

`checkedAt` 是實際核對日期，`source.publishedOn` 是來源發布／修正日，`source.rocYear` 是來源適用年度；三者不可混用。完成內容核對才更新日期，部署或自動連結檢查不算內容核對。

`official-page` 為官網核對，`current-notice` 為當期公告核對，`contact-confirmed` 僅供實際取得窗口確認後使用；目前資料未聲稱已聯絡任何機構。

受理狀態無證據時用 `inquiry`。`ongoing` 只用於官方明確持續提供的服務／受理，`open` 須有當期公告及明確截止日。`startsOn`、`endsOn` 僅能使用公告確定的日期；分季核銷或事件發生後幾個月的相對期限寫在 `applicationPeriod`，不可將某季期限當成整個方案永久截止。

超過 `endsOn` 自動顯示已截止，不推定次年度延續。公告未開放的開始日到達後轉為需詢問，避免自動聲稱已開放。沒有實際受理證據且無確定截止日的項目，不在卡片重複貼空泛狀態標籤；詳細規定仍明示收件、預約或審查程序。受理中、常態辦理、截止或有確切截止日才顯示重點標籤。

公開項目採三階段，不因剛逾期就丟掉聯絡線索：

1. 距 `checkedAt` 不超過 `reviewAfterDays`（含當天）：完整顯示已核對內容。
2. 超過規則複核週期、距最後核對未超過365天（含第365天）：僅顯示單位、窗口、電話、可用官方連結及原核對日期；「能幫什麼」改為「金額與期限請向窗口確認」。提醒統一使用「最後核對：日期」「申請規定可能已更新，請先打電話向窗口確認。」，不顯示逾期天數，排序置於完整資料之後。舊服務標題、金額、期限、名額、資格、文件、申請流程與受理標籤都不輸出，避免從收合內容、列印或縣市公開頁洩漏舊規定。
3. 距最後核對超過365天：才隱藏。聯絡資料保留上限固定為 `CONTACT_RETENTION_DAYS = 365`，獨立於金額、期限等規則的 `reviewAfterDays`，不再乘以六倍。該服務不再進入結果或已選列印清單；22縣市官方窗口仍另行保留，不代表當地沒有服務。

`reviewEvidence` 可記錄負面證據，不必等到複核週期到期：`not-found` 表示實際查到官方網址404，立即改為僅窗口且不輸出該失效網址；聯絡網址失效時可改用同筆已收錄且未查到失效的正式來源網址。兩個網址均失效時仍保留電話；若連電話也沒有則隱藏。`discontinued` 表示有官方停辦公告，立即隱藏，應以 `sourceUrl` 留存公告依據。只記錄實際觀察與臺灣日期，不將暫時逾時或無法讀取直接冒充404，也不將本站已有的年度截止推定為永久停辦。

正面證據須實際重讀內容並更新 `checkedAt`；若曾有負面證據，另加同一 `url` 的 `content-verified` 紀錄，日期不得早於負面證據，也不得晚於 `checkedAt`，才解除該網址的負面紀錄。紀錄依實際觀察順序附加；同一天的事件以陣列先後決定新舊，因此同日先複核、後來又查到404，仍立即降級。解除停辦需核實正式恢復辦理，不能僅因頁面恢復HTTP200就解除。單純連結檢查成功不新增 `content-verified`、不更新 `checkedAt`、不延長有效期，也不自動清除錯誤紀錄；未來日期的觀察不提前生效。

主查詢頁使用瀏覽器臺灣日期與 `RESOURCE_UPDATED_AT` 的較晚者，涵蓋首次載入、每分鐘更新、視窗重新聚焦、重新顯示與列印，避免手機時鐘過早造成零結果。核對日期不得晚於實際今天由資料測試檢查；執行時不因裝置日期早於核對日而隱藏，負數資料年齡以0計算。四個縣市頁依每日 ISR 重新產生狀態；這只是網站既有資料的日期與已記錄證據判斷，沒有新增背景爬蟲、資料庫、外部機構自動查核或通知排程。

建議早療與限期方案每月或更頻繁確認，常態窗口每季確認；年度換版、機構公告或連結失效時，優先重新核對。具體週期記錄在各筆資料。網站不會因此發送聯絡訊息。

`prebuild` 先執行 `npm run warn:resources`，採建置主機的臺灣日期，僅向建置紀錄輸出 `console.warn`，不因到期項目使建置失敗，也不更改核對日期。第一組列目前完整顯示、未來1至28天內會轉為僅窗口的公開項目；轉換日為 `checkedAt + reviewAfterDays + 1`。第二組列目前僅窗口、未來1至30天內會隱藏的項目；隱藏日為 `checkedAt + 366`，第365天仍保留。兩組均依實際轉換日分組，組內列ID、名稱、單位及最後核對日期；已隱藏、暫不公開或因停辦等證據不會發生該轉換的項目不混入提醒。

以2026-10-20資料計，11/18有7筆公開項目會降級（另1筆30天週期候選尚未公開），10/21起進入28天提醒範圍。首次複核宜在11月中以前完成，可分10月底、11月初與11月上旬逐批實際核對，以各批真正核對日更新，讓下次到期日自然分散。

本次擴充僅有官方索引內容、原頁與官方 PDF 均無法直接複核的醫院候選，先不納入公開清單；不可為達單位數目標降低核對標準。

## 篩選與隱私

查無結果時直接顯示所選22縣市範圍內的官方窗口（含中部四縣市），並提供1957福利諮詢及1966長照專線的撥號按鈕與正式來源；無需再展開「相關網頁」。這些聯絡線索不計入補助結果、不附受理標籤，也不帶入個人篩選條件。1966仍須依需求評估，顯示專線不表示已符合長照資格。正常有結果時只為尚未逐筆整理的縣市顯示窗口，避免同頁重複兩組窗口。

1957與1966在此作為常設查詢窗口，與22縣市窗口一樣獨立於個別方案的365天期限；即使方案全部久未複核，仍可找到電話。但仍共用 `resourceContactLead` 的負面證據：已知404網址不輸出、已公告停辦的服務不顯示，不能從原始資料繞過停辦或錯誤紀錄。

畫面依序選擇疾病、查詢縣市、協助需求，三項皆完成並提交後才顯示結果。初始不顯示資源卡片、結果數或空白討論清單。修改條件時先返回步驟，重新提交才套用；已選資源保留，與新條件不符時明示差異。政府常用網站及 22 縣市窗口集中於頁面上方可展開的「相關網頁」，不計入方案數。

同欄複選為 OR，不同欄為 AND。縣市以 `regions` 陣列複選，可同查雲林與彰化，保留雲林戶籍型方案及彰化就醫型服務。它只表示搜尋範圍，不代表使用者已具備任一地戶籍、居住或就醫資格，也不寫入個人地理欄位。舊的 `region` 單選呼叫及分別地理欄位匹配仍相容；未知戶籍或就醫地不能推定與居住地相同。

病名只作導覽，不等於身障、罕病、重大傷病或補助資格。不進行自動資格決定，年齡與身分補充欄僅留在紙本手寫。篩選值及已選清單只在記憶體，不寫入 URL、localStorage、後端或分析事件。每筆「回報資料有誤」只開啟官方 LINE 並預填公開 `resource_id`，由使用者自行決定是否送出；不附病別、縣市、需求或清單，也不增加追蹤事件。

主頁維持先篩選再顯示，另提供 `/rehab-resources/changhua`、`nantou`、`taichung`、`yunlin` 四個真正有不同在地內容的公開頁。服務摘要、正式來源與日期由伺服器產生，完整條件也在 HTML 內，附與可見單位一致的 ItemList、canonical、麵包屑及 sitemap；固定地區內容網址不是患者篩選 URL。三篇現有相關文章已有內部連結；日後中風復健文章完成時，應依文章情境補連到資源查詢。

頁尾資源連結停用預先載入。沒有新 API、資料庫或 AI 呼叫；列印與 PDF 儲存使用瀏覽器功能，每項服務附本機產生、指向官方申請說明的 SVG QR code，不呼叫外部 QR 服務。資料實質變更經使用者核准、建置部署後才公開。

## 驗證

執行 `npm run test:resources` 檢查資料契約、22 縣市覆蓋、地區判斷、截止及複核規則。完整建置也會執行此測試。發布前再依專案 SEO 內容流程執行驗證、lint 與 build，並檢查手機與 A4 列印結果。
